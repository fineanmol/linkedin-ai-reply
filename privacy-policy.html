Privacy Policy

This page describes exactly which data the extension reads, where it is stored, and which AI provider it is sent to — depending on the backend you select.

⚡ The Short Version

  • We (the extension authors) run no servers and collect nothing. There is no analytics, telemetry, or tracking.
  • All extension data is stored in your browser's chrome.storage.local.
  • Ollama (local): AI generation runs on your own machine. Nothing is sent to a cloud AI provider.
  • Gemini (cloud): the text needed to generate a draft is sent to Google.
  • Claude (cloud), via the local Claude Code bridge or your Anthropic API key: that text is sent to Anthropic.
  • Auto mode uses Ollama when it is running and otherwise falls back to Gemini (cloud).
  • Nothing is ever posted, sent, or published to LinkedIn automatically. You copy, paste, and post everything yourself.

🤖 AI Backends & Data Flow

Ollama — local

  • Requests go to Ollama on your own machine (http://localhost:11434).
  • No prompt is sent to a cloud AI provider.

Gemini — Google cloud

  • Prompts are sent to Google's Generative Language API (generativelanguage.googleapis.com) with your own API key.
  • Google's handling of that data is governed by Google's Privacy Policy and the Gemini API terms.

Claude via the Claude Code bridge — Anthropic cloud

  • The extension sends prompts to a small bridge running on your machine (http://localhost:11435, started with npm run bridge).
  • The bridge passes each prompt to the Claude Code CLI, which sends it to Anthropic using your Claude Code login. The data therefore leaves your device even though the bridge itself is local.

Claude via the Anthropic API — Anthropic cloud

  • Prompts are sent directly to api.anthropic.com with your own API key.
  • Anthropic's handling of that data is governed by Anthropic's Privacy Policy and its commercial terms.
Note: The extension authors never receive your data. When you choose a cloud backend, the provider you chose (Google or Anthropic) receives the prompt under its own terms.

🕵️ Background Profile Reading (off by default)

  • Two features can open hidden LinkedIn tabs to read another person's profile and recent activity: deep welcome-message drafts and the Content Calendar's friend-post scrape.
  • This only happens when you turn on Settings → Advanced → Allow background profile reading and then click the feature. It never runs on a schedule.
  • LinkedIn's User Agreement prohibits automated scraping, and each visit shows up to that person as a profile view. Leave it off unless you accept that risk.
  • The text read this way is used only to build the prompt and is sent to your selected AI backend (cloud for Gemini/Claude).

💾 Local Storage

The extension stores the following only in your browser (chrome.storage.local):

  • Settings: backend, models, URLs, reply length, toggles.
  • Your Gemini API key, Anthropic API key, and bridge token, if you enter them. These are never sent to LinkedIn pages.
  • Your display name and profile URL (detected on LinkedIn).
  • Style profile: manual examples plus up to 100 approved replies.
  • Reply history: recent generated replies with a snippet of the comment.
  • Engagement queue and comments log: posts you queued, your drafts, and comments you marked as posted.
  • Connections queue: new connections' names, headlines, and draft messages.
  • Content Calendar: draft posts, plus the friend source posts and image links they were adapted from.
You can clear this at any time via Settings → Advanced → Reset All Data or by removing the extension.

🚫 What the Extension Does Not Do

  • It never posts, comments, sends messages, or sends connection requests on LinkedIn.
  • It does not use LinkedIn's API.
  • It has no analytics, telemetry, crash reporting, or advertising SDKs.
  • It does not sell, rent, or share data with anyone other than the AI provider you select.
  • It does not require an account.
